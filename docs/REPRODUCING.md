# Reproduce the manuscript experiments

## Recompute retained records

Run from the repository root:

```text
python scripts/recompute_results.py
```

The script verifies `MANIFEST.sha256` and reproduces Tables 6–10 and 12 from the saved data. Table 8 places the Chen comparator before the proposed Fuzzy-PID. Outputs go to `reproduced_results/`; `--output` chooses another directory.

`check_error_decomposition.py` reconstructs the same processed inputs from the saved encrypted trajectory and matches the applied outputs using the one-sample delay. It reproduces fitting RMSE 0.2095 and RNS-CKKS RMSE 1.91e-6 in normalized command units. There are 1229 trajectory samples and 1228 observed input/output pairs, because the last request has no subsequently applied output in the saved trace. All matched commands are unsaturated. These data are separate from speed-tracking errors.

`check_approximation.py` evaluates the four Section 6.2 polynomial partitions on 12,000 shared uniform inputs, seed 20261020. `--refit --grid base_8x8x6` regenerates the selected least-squares fit with 10×8×7 training points per cell into a separate output directory. Other reported grid names are `global_1x1x1`, `coarse_4x4x3` and `fine_16x16x12`. BLAS/LAPACK differences can affect the last coefficient digits; original arrays are retained.

`plot_results.py` generates Figures 3–6 from the retained trajectories into `reproduced_results/figures/`. Generated plots use portable fonts and can differ in styling from the manuscript.

## Run new client/server experiments

Install NumPy 2.3.5, Matplotlib 3.10.8 and TenSEAL 0.3.16 on the analysis/client machine. The recorded Python 3.10 server uses NumPy 2.2.6 and TenSEAL 0.3.16. The software versions and experiment settings are summarized in `docs/PARAMETER_SOURCES.md`. Copy the folder to both hosts.

On the server:

```text
python scripts/run_experiment.py --case fuzzy --role server --workdir runs/server_fuzzy
```

On the client:

```text
python scripts/run_experiment.py --case fuzzy --role client --host SERVER_IP --workdir runs/client_fuzzy
```

Replace SERVER_IP with the server address and use a new work directory for every run. The original transport is intended for the trusted-LAN experiment. Keys are freshly generated by the vehicle; only the public evaluation context is sent to the cloud.

| Case | Port | Paper experiment |
|---|---:|---|
| pid_plain | 47857 | Plaintext PID, Section 6.3 |
| ckks_pid | 47862 | CKKS-PID, Sections 6.3 and 6.6 |
| fuzzy | 47856 | Chen-based, proposed fuzzy, plaintext polynomial and encrypted polynomial controllers, Sections 6.4–6.6 |
| partitions | 47858 | Fuzzy reference and the four reported polynomial grids, Section 6.2 |
| conditions | 47843 | Four operating conditions, three repetitions each, Section 6.7 |

`--role prepare` sets up the sources, route and coefficients without executing a controller. Full-course experiments stop at the recorded geometric completion criterion; the operating-condition runs use a fixed 1200-sample window.

The formal vehicle update is implemented in these runners, with a 0.1 s sample interval, 2.9 m wheelbase, nominal acceleration gain 3, nonnegative speed and the recorded initial state. The main full-course and operating-condition campaigns retain their recorded reference lookup methods.

Both encrypted controllers use RNS-CKKS. CKKS-PID uses the historical `pid_packed` code path: slots [e,I,de] and encrypted gains [Kp,Ki,Kd], followed by a cloud slot sum. CKKS-Fuzzy-PID uses six packed features, one ciphertext squaring, plaintext weighting and a cloud slot sum. Its region index is sent in plaintext.

The next-boundary actuation rule allows one outstanding request and holds the previous command while waiting. CKKS-PID retains its startup checks and warmup procedure; those requests are excluded from formal latency metrics. New timings and schedules depend on hardware, network and process scheduling. Frozen paper records remain in `data/`.
